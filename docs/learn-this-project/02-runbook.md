# 02 — Runbook

Copy-pasteable instructions to install, run, test, and debug this project.

## Prerequisites

| Tool | Version (declared in `mise.toml`) | Install |
|---|---|---|
| **mise** | Latest | `brew install mise` (macOS) or see <https://mise.jdx.dev/getting-started.html> |
| **Python** | 3.12 | `mise install` (reads `mise.toml` and pins Python 3.12) |
| **uv** | Latest | Installed automatically by `mise install` |
| **AWS CLI / profile** | An AWS profile with S3 read/write + STS permissions on a bucket matching `{account_alias}-{region}-data` | `aws configure --profile <name>` |
| **pandoc** | 3.9 | Only needed for the docs task; `mise install` handles it |
| **claude** | Latest | Installed automatically by `mise install` (for the learning skills) |

Verify:

```bash
mise ls python --current   # should show 3.12
uv --version
aws sts get-caller-identity --profile <your-profile>
```

## First-time setup

Run these from the repo root:

```bash
# 1. Install language tools + uv + pandoc + claude pinned by mise.toml
mise install

# 2. Create .venv (idempotent — won't clobber an existing one)
mise run venv-create

# 3. Install all Python dependencies (core + dev + test extras)
mise run inst

# 4. Configure AWS profile (one-time per machine)
cp .env.example .env
# edit .env so AWS_PROFILE="<your-profile-name>"

# 5. Smoke-test that env loaded
python -c "from delta_lake_and_polars_basic.one.api import one; print(one.s3_bucket)"
# Expected: prints something like 'axiomcard-us-east-1-data' (your account alias + region)
```

The smoke-test in step 5 is the fastest way to catch `.env` problems — if it raises `KeyError: 'AWS_PROFILE'` you forgot step 4.

## Day-to-day commands

| Task | Command | What it does |
|---|---|---|
| Install / re-sync deps | `mise run inst` | `uv sync --all-extras` (idempotent) |

List every task with `mise tasks ls`.

## Running locally — the 16 example scripts

There are 16 runnable scripts under `examples/`. Each is fully self-contained: run it from any directory (it imports `path_enum` for paths). Run them one at a time so the output is legible.

```bash
# Module 02 is pure local — no S3 needed. Start here if AWS isn't ready yet.
python examples/02-polars-etl/s01_column_ops.py
python examples/02-polars-etl/s02_dedup_agg.py
python examples/02-polars-etl/s03_transform.py

# Module 00 is the golden reference (round-trip on S3)
python examples/00-minimal-poc/s01_minimal_poc.py

# Module 01 — Delta write modes
python examples/01-delta-read-write/s01_overwrite.py
python examples/01-delta-read-write/s02_append.py
python examples/01-delta-read-write/s03_error_mode.py     # expected to raise + catch DeltaError

# Module 03 — merge
python examples/03-merge-upsert/s01_basic_upsert.py
python examples/03-merge-upsert/s02_credit_profile.py

# Module 04 — time travel
python examples/04-time-travel/s01_version_read.py
python examples/04-time-travel/s02_history.py

# Module 05 — vacuum + schema evolution
python examples/05-vacuum-schema/s01_vacuum.py
python examples/05-vacuum-schema/s02_schema_evolution.py

# Module 06 — capstone. Run in order.
python examples/06-full-etl/s01_bronze_write.py
python examples/06-full-etl/s02_silver_etl.py
python examples/06-full-etl/s03_incremental.py
```

Recommended ordering: `02-polars-etl/` → `00-minimal-poc/` → `01` → `03` → `04` → `05` → `06`. The Polars-only module first so you confirm the compute stack works before adding S3.

**What to look for in stdout:** every script prints intermediate DataFrames or shapes; nothing is silent on success. If you see no output the script is hung — check AWS connectivity.

## Tests

The test infrastructure exists, but the project currently has **no actual test files** beyond `delta_lake_and_polars_basic/tests/__init__.py` and `tests/helper.py`. `mise run test` and `mise run cov` will pass vacuously. The plumbing is ready for you to add `tests/test_<module>.py` files that use the helper:

```python
# Pattern (see tests/helper.py)
from delta_lake_and_polars_basic.tests.helper import run_cov_test

def test_something():
    assert 1 + 1 == 2

if __name__ == "__main__":
    run_cov_test(__file__, "delta_lake_and_polars_basic.<module>")
```

This shape lets you double-click the test file in your IDE and get a coverage HTML report scoped to just that module — see §1.4 of `01-knowhow-inventory.md`.

## Common failures and fixes

| Symptom | Cause | Fix |
|---|---|---|
| `KeyError: 'AWS_PROFILE'` on first import of `one` | `.env` not present or missing the var | `cp .env.example .env` and set the value |
| `botocore.exceptions.NoCredentialsError` | Profile exists but credentials expired | `aws sso login --profile <name>` (or your usual refresh) |
| `botocore.exceptions.ClientError: AccessDenied` writing to S3 | The IAM role for your profile can't write to the auto-derived bucket | Either grant write access on `{account_alias}-{region}-data`, or override `one.s3_bucket` and `one.s3dir_root` before running |
| `deltalake._internal.DeltaError: Schema mismatch` | You ran `s02_append.py` after evolving the schema in `s02_schema_evolution.py` | Run `s3dir_example.delete(bsm=bsm)` on the table prefix or restart from the cleanup step at the top of the script |
| `mise run release` (or other setup-* tasks) fails immediately | Those tasks shell out to `.mise/tasks/*.py` scripts that aren't vendored in this repo | Expected; those tasks are not part of the learning flow |
| `pl.read_delta(...)` returns zero rows after a fresh write | Eventual consistency on S3 — extremely rare on a single-writer flow | Re-run; if persistent, check `DeltaTable.history()` to confirm the commit landed |
| `python examples/...py` works but `mise run` doesn't pick env | `mise.toml` declares `_.file = ".env"` — confirm the file is named exactly `.env`, not `.env.local` | Rename or symlink |

## Where to look when something breaks

- **AWS-side:** Open S3 Console, navigate to `s3://{your-bucket}/projects/delta_lake_and_polars_basic/`. Each script writes into its own sub-prefix; the layout is visible at a glance.
- **Delta commit log:** `DeltaTable(uri, storage_options=one.polars_storage_options).history()` prints every commit with `operation`, `timestamp`, and any `operationParameters`.
- **Schema drift:** `DeltaTable(uri, ...).schema()` returns the current schema, including post-evolution columns.
- **CLI auth:** `aws sts get-caller-identity --profile <name>` confirms the profile resolves; `aws s3 ls s3://{bucket}/` confirms list permission; `aws s3 cp /tmp/test.txt s3://{bucket}/<prefix>/test.txt` confirms write.
- **Coverage report:** `mise run cov && mise run view-cov` once test files actually exist.
