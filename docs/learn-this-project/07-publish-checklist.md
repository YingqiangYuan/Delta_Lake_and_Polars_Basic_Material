## 4. README co-write outline (English, sectioned)

The publish skill walks the user through these sections one at a time in D-mode (co-write). For each, print the goal, ask the prompts one at a time, draft the section from the user's actual words.

### § Project description
- **Goal:** In ≤120 words, tell a reader what this project is and why it exists.
- **Prompts:**
  - "In one sentence, what is this project?"
  - "What real-world problem does the tech stack it uses (Delta Lake + Polars on S3, no Spark) actually solve?"
  - "Who would care about this — what kind of engineer or team?"
- **Length:** 80–120 words.

### § Install & run
- **Goal:** Show the minimum command sequence from clone to "running output on screen", without front-loading prerequisites.
- **Prompts:**
  - "What's the minimum command sequence — from `git clone` to first running script — that you'd give a friend?"
  - "Which AWS prerequisite is the one most likely to trip them up, and what would you tell them about it in one line?"
- **Length:** 50–100 words.

### § What it teaches (or "What's inside")
- **Goal:** Quick map of the 16-script curriculum so a reader knows what to open first.
- **Prompts:**
  - "If a reader has 5 minutes, which one script should they open and what would they learn?"
  - "What's the one design choice in this project you'd most want a reader to notice?"
- **Length:** 80–120 words.

### § What I learned
- **Goal:** Concrete, specific takeaways. NO "I learned a lot" filler.
- **Prompts:**
  - "What surprised you most while building this — something you didn't know was true before?"
  - "If a friend asked 'what was the actual point of doing this?', what would you say?"
  - "What was the hardest part, and how did you push through?"
- **Length:** 100–150 words.

### § What I'd do next (optional but recommended)
- **Goal:** Show forward-looking judgment. Frames the project as the start of a thread, not a finished thing.
- **Prompts:**
  - "If you spent another week on this, what would you add first?"
  - "What's the one thing missing that you'd defend as deliberate rather than an oversight?"
- **Length:** 50–80 words.

**Total README target:** 300–500 words. English only.

**Voice guardrails:**
- Past tense for what was built ("I built", "I wrote"), present tense for what the project is ("This project is", "It teaches").
- First person singular. Never "we". Soften any "in this tutorial" / "this project teaches" / "course" / "lesson" phrasing the user accidentally uses.
- Specific over generic — "merge into a 200-row Delta table" beats "demonstrates upsert".

## 5. Hostile-scan rules for Audit mode

Assume a hostile reader scanning the repo with "did this come from a tutorial?". Find every tell. Each rule has a severity.

### 5a. File-pattern flags 🔴 HIGH

| Pattern | What it signals |
|---|---|
| `README-*.md` (any non-root README at repo root) | Multi-language teaching READMEs |
| `*-cn.md`, `*-tutorial.md`, `*-course.md`, `*-lesson.md` | Translation / curriculum naming |
| `TICKET.md`, `LESSON.md`, `CHECKLIST.md`, `EXERCISES.md` | Teaching-checklist filenames |
| `docs/learn-this-project/`, `docs/learn-*/`, `docs/tutorial*/`, `docs/lesson*/` | Mentor analysis or course archives |
| `.claude/skills/learn-this-project-{absorb,quiz,elevate,interview,demo,publish}/` | Sibling teaching skills (the meta one is OK) |
| `.claude/skills/lesson-smith-*` | Adjacent toolkit skills from the learning system |

### 5b. README phrase flags 🔴 HIGH (in repo-root README.md / README.rst only)

Phrases that signal teaching origin or coursebook tone. Grep these case-insensitively:

- `"this tutorial"`, `"this lesson"`, `"this course"`, `"course material"`
- `"the mentor"`, `"as a student"`, `"as a learner"`
- `"we will learn"`, `"we'll learn"`, `"in this project we"`, `"the goal of this lesson"`
- `"mastery gate"`, `"learning checklist"`
- `"as shown in module N"`, `"as you saw in chapter"`
- First-person *plural* learning prose ("we learned X by doing Y") — first-person singular is fine; plural reads as classroom.

### 5c. Commit-message phrase flags 🟡 MEDIUM

Same phrase set as 5b, applied to `git log --all --format="%s%n%b"`. Also flag:

- Generic templated subjects: `"chore: setup"`, `"initial commit"` for any commit past #1, `"fix typo"` as a standalone commit
- Bracketed prefixes like `[lesson]`, `[module-N]`, `[tutorial]`
- All commits dated within the same 24-hour window (looks templated; a hostile reader will notice)

### 5d. Git ref flags 🔴 HIGH

`git tag --list` and `git branch --all` flagged names:

- `tutorial-base`, `tutorial-start`, `original`, `pristine`, `from-tutorial`, `v0-from-course`
- `lesson-N`, `module-N`, `chapter-N`
- `student-fork`, `learner-fork`

### 5e. Residual directory flags 🔴 HIGH

- Any `.claude/skills/learn-this-project-*/` directory other than `learn-this-project-meta/` (which is allowed).
- `docs/learn-this-project/` or any `docs/learn-*/`.
- Any `.lesson-smith*/`, `.mentor*/`, `tmp/publish-commit-plan.md` (the commit cheat-sheet itself — useful during transform, an obvious tell if shipped).

### 5f. Hygiene flags 🔵 LOW (not teaching-specific, but ugly)

- `.idea/`, `.vscode/` if committed
- `__pycache__/`, `*.pyc` if committed
- `.venv/` if committed
- `*.egg-info/` (e.g., `delta_lake_and_polars_basic.egg-info/`)
- `.DS_Store`
- `htmlcov/`, `dist/` if committed

### 5g. Suspicious symmetry flags 🟡 MEDIUM (heuristic)

Hard to detect mechanically; surface as judgment calls. Look for:

- Multiple files with identical multi-line comment banners or identical opening docstrings (e.g., the `# -*- coding: utf-8 -*-` line on every file is *normal*; an 8-line banner block describing "This is a teaching example" on every file is templated).
- All example scripts with identical structure to a comment-character level — a hostile reader spots "these were obviously generated from one template, none was hand-written".
- Per-module READMEs that are clearly slot-filled from the same outline (same H1/H2/H3 sequence, same bullet point counts, same word counts).

### 5h. Severity summary

- 🔴 **HIGH RISK** — fatal-on-detection. Block "Transform complete" until cleared (or user explicitly accepts).
- 🟡 **MEDIUM RISK** — visible to a careful reader. Surface, suggest fix, allow user to defer.
- 🔵 **LOW RISK** — hygiene only. Surface, fix on user's choice.

The Audit report should group findings by severity and offer "fix on consent" for each — applying the same `rm` / `Edit` patterns the Transform mode uses.
